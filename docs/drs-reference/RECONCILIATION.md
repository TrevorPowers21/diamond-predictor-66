## Findings (things to confirm before production — none block adopting this as the baseline)

1. **DP attribution is skewed per-player (design).** `_dp_opportunity_charge` (engine.py:207) *always*
   debits 2B(4) and SS(6) on every GB-DP opportunity, regardless of who fielded it, while credit
   (`_dp`) goes to the actual turners (which can include 3B/1B). Nets to zero league-wide, but an SS
   eats charges for DP balls hit to the left side it never touched. **+ latent bug:** the router's
   `is_dp_opp` (engine.py:277) tests `ev.bb_type=="G"` with **no** `pitchResult` fallback, while the
   fixture derivation (normalize.py:118) uses `ev.bb_type or bb_type_from_result(...)`. They agree on
   this sample only because all 3 opps had an explicit `/G`. On a full season, groundouts that carry
   the type only in `pitchResult` will be counted by the fixture but missed by the router → charges
   under-fire → the net-zero invariant breaks and DP drifts positive league-wide.

2. **Blocking is the softest component.** WP/PB is a *positional heuristic* (`detect_pbwp`,
   engine.py:133), not real WP/PB codes — that's Open Item #4, unresolved. Also an **operator-precedence
   bug** at engine.py:152-153: `A and B and C or D` groups as `(A and B and C) or D`, so the 2nd→3rd-base
   branch bypasses the outer `b0!=b1 / sum(b1)<=sum(b0)` guards. Low impact today (mid-at-bat base count
   can't increase, so the guards are usually satisfied anyway) but fragile — parenthesize it.

3. **Framing is an exact-match allowlist** (`TAKEN_STRIKE`/`TAKEN_BALL`, engine.py:100). Complete and
   correct for this data (all taken pitches are `Ball`/`Strike Looking`/`Walk`/`Strikeout (Looking)`;
   `Foul`/`Strike Swinging` correctly excluded; `Hit By Pitch` correctly excluded). BUT any full-season
   label variant silently drops with **no exception logged**. Recommend: route a taken-but-unrecognized
   `pitchResult` to the exceptions log instead of dropping.

4. **Production-ingest hardening (from the date-organized upload discussion).** `load_rows`
   (normalize.py:32) assumes every file is a Standard export — no `atbatDesc`-presence guard, so it will
   try to parse a Pitch Log export's rows. And it crashes on `int(r["pitchNumInGame"])` /
   `r["gameId"]` if a file lacks those columns. Add an export-type guard + column presence check before
   the full-season, mixed-export upload.

## Confirmed correct / faithful to spec

Dedup; FC credit-only (never debits range, verified in isolation across all 8 FC events); errors as
max-punishment stored separately, with the `outs_made` split (ROE→full debit, error-with-out→
advancement-only); `xOut=1−xAVG` + fallback ladder logging `PARTIAL_TRACKING`; arm kill uses `continue`
so the thrown-out runner isn't double-counted as a hold; constants stamped `PLACEHOLDER_MLB_v0` in
every row; TYPE_MISMATCH / PARTIAL_TRACKING exceptions match expected exactly.

## Bottom line

The engine is solid and faithful to the spec — safe to adopt as the reference implementation. The four
findings are for Peyton/Sam before it goes to production; none of them block the parity baseline. Real
dRS numbers remain gated on the full-season export + the D1 RE24 constants derivation.

## Fixes applied — v0.2.0 (2026-08-03, Trevor's go)

All four findings fixed on `feature/defensive-runs-engine`. Engine folded into `scripts/drs/`
(the received copy under `docs/drs-reference/drs/` was superseded and removed). `engine_version`
→ `drs-engine-0.2.0`. Suite is now **26 tests, 0 failing** (was 22 + 2 new regression tests + 2 DP
redesign assertions). Made 3.9-compatible via `from __future__ import annotations`.

1. **DP → per-fielder net accounting (design fix).** Killed the hardcoded 4/6 charge. One shared
   `dp_opportunity_shares()` / `dp_conversion_shares()` (in `normalize.py`) is used by BOTH the fixture
   derivation and the router, so their opportunity counts can't diverge. Opportunities land on the
   fielder who fielded the ball (chain[0] on outs, error/FC fielder, responsibility-share on infield
   hits); conversions on the same fielder; `dp_runs = (conv − league_rate × opp) × RUNS_PER_DP`. Nets
   to zero league-wide (raw 5.6e-17). On the fixture this newly and correctly attributes: G. Gallaher
   2B +0.267 (turned the 463 GDP), E. Paulsen 1B −0.133 (booted E3 DP ball), J. Schaffner SS −0.133
   (non-converted DP grounder he fielded) — all previously masked to 0.000 by the 4/6 hardcode.
   (`half_innings` dropped 1 for the 2B/SS: the old phantom 4/6 touches had inflated their inning set.)
2. **Blocking precedence** parenthesized to `A and B and (C or D)` — the base-state guards now apply to
   both advancement branches.
3. **Framing** now classifies every pitch (`framing_class`); an UNKNOWN result WITH a probSL logs
   `NEW_VOCAB` instead of silently dropping. Zero on this data (all labels recognized), so the exceptions
   log stays identical (13).
4. **Ingest hardening**: `load_rows` skips non-Standard files (no `atbatDesc`) and bad rows with a logged
   reason (returned in `skipped`), guards the sort key, and accepts directories/globs for the
   date-organized upload.

**Regression tests added:** (R1) DP opportunity count fixture == router over any dataset; (R2) no probSL
pitch with an unrecognized result exits framing unlogged (+ a synthetic mechanism check).

Golden `player_season_defense.expected.csv` / `exceptions_log.expected.csv` regenerated at 0.2.0. Parity
vs the original v0.1.0 golden: **only** the 3 DP rows changed value (+ the `engine_version` stamp);
everything else byte-identical. The committed test suite validates via invariants (not a golden diff) and
is CI-safe — Tier 1 always runs; Tier 2 runs only when `DRS_FIXTURE_DIR` points at the Standard CSVs.
Still gated on the full-season export + D1 RE24 for real numbers.
