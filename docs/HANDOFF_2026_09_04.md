## ⚠️ TRAPS THAT ACTUALLY BIT — read before debugging anything

Full reasoning with citations: `docs/PHILOSOPHY.md`.

- ★ **Read a table's unique constraints before aggregating.** `player_predictions` is keyed on
  **five** columns *including `season`*. Six wrong conclusions in two days were all this shape:
  grouping without `division`, then `updated_at`, then `season`. One nearly became a recommendation
  to delete **7,255 legitimate rows**.
- **Prove two things are comparable before diffing.** Same generation · same side (a TWP carries
  both on ONE row) · same field name (`market_value` is `nil_valuation` on board snapshots) · **same
  metric** (Team Builder shows pRV+ for pitchers, the profile shows *PR+*) · **same population** (the
  TWP own-side rule governs SNAPSHOTS, not raw prediction rows).
- **Verify the thing works, not that the command returned.** `exec_sql OK` while the transaction
  rolled back. An **RLS-blocked write returns success with 0 rows and no error**.
- **An empty result looks exactly like nothing being wrong.** A SQL-Server-style `LIKE 'gm[_]%'`
  matched zero rows and nearly printed as clean. `information_schema` is **privilege-filtered**.
- **Verify config on BOTH databases.** Gate B, and its 09-02 repeat when a staging RLS finding was
  reported as a prod hole that never existed.
- **`buildsLoading` is `isLoading` — false whenever cached data exists.** It does not cover a
  background refetch. That single distinction was bug #2.
- **`nil_value_overridden` is not a column.** It is `production_notes` JSON. Writing it as a column
  errors outright.
